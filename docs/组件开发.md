# 组件开发指南

组件是独立于扩展主包的可安装单元。扩展只负责发现、校验、启停与（对原生组件）拉起进程；组件不修改扩展代码。

## 目录布局

```
<components.dir>/<id>-<version>/
├── component.json      必需
├── native-audio-output 原生入口（kind=native）
└── ...                 组件自带资源
```

默认 `<components.dir>` 为 `<globalStorage>/components/`，可用 `neteaseMusic.components.dir` 修改。随扩展分发的组件放在 `<extension>/components/<platform>-<arch>/`。

## 清单字段

```json
{
  "schemaVersion": 1,
  "id": "native-audio-output",
  "name": "Native Audio Output Engine",
  "version": "0.1.0",
  "kind": "native",
  "platform": "linux",
  "arch": "arm64",
  "entry": "native-audio-output",
  "sha256": "e8b0…",
  "backend": "alsa",
  "protocol": "naoe-frame-v1",
  "description": "ALSA 直连 / PipeWire 原生输出",
  "formats": [
    { "sampleRate": 48000, "bits": 24, "channels": 2, "sampleFormat": "s24le" }
  ],
  "ui": {
    "entry": "webview.js",
    "title": "示例面板",
    "width": 480,
    "height": 320
  },
  "minExtensionVersion": "0.1.0",
  "homepage": "https://example.com"
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 唯一 id；原生引擎固定为 `native-audio-output` |
| `kind` | `native` 或 `ui` |
| `platform` / `arch` | `linux` / `win32` / `darwin`，`x64` / `arm64`；`any` 表示不限制 |
| `entry` | 相对组件目录的入口文件 |
| `sha256` | 入口文件 SHA-256；安装时校验并回写 |
| `backend` | 原生组件的后端名，用于 UI 展示 |
| `protocol` | 原生进程协议，当前 `naoe-frame-v1` |
| `formats` | 清单声明的能力，用于离线展示；真实能力以 `--probe` 为准 |
| `ui` | 第三方 UI 预留字段 |

平台不匹配会标记为 `incompatible`；入口缺失或哈希不符标记为 `invalid`。

## 组件 zip（自动下载）

当原生引擎未安装/未启用时，扩展会按 `neteaseMusic.components.downloadUrl` 下载组件 zip 并安装。zip 格式要求：

- 根下放组件目录内容（`component.json` + 入口文件），可带一个顶层目录（安装时自动压平）。
- 支持 stored 与 deflate 两种压缩方法；条目名不允许 `..` 或绝对路径；条目数上限 4096。
- `component.json` 中的 `sha256` 必须与入口文件一致，否则安装失败。
- 参考实现：`scripts/build-native.mjs` 的 `writeZip()` 会为每个平台产出 `components-zip/netease-native-audio-output-<platform>.zip`（stored），可直接托管后填入 `downloadUrl`。
- 仅启用 `neteaseMusic.components.autoDownload = true` 时自动下载；组件页的「安装」按钮同样支持直接选择组件目录或 zip。

## 原生组件协议（naoe-frame-v1）

### 命令行

| 参数 | 行为 |
| --- | --- |
| `--probe` | 枚举设备与格式，stdout 输出一行 JSON 后退出 |
| `--serve` | 进入播放会话：stdin 读帧，stdout 写事件 |
| `--version` | 输出版本与协议 |
| `--backend alsa\|wasapi\|null` | 强制后端，主要给测试用 |

### probe 输出

```json
{
  "ok": true,
  "version": "0.1.0",
  "protocol": "1",
  "backends": ["alsa"],
  "devices": [
    {
      "id": "hw:0,0",
      "name": "Built-in Audio",
      "backend": "alsa",
      "isDefault": false,
      "formats": [
        { "sampleRate": 48000, "bits": 24, "channels": 2, "sampleFormat": "s24le" }
      ]
    }
  ]
}
```

### 帧

每帧：`type`（1 字节）+ `length`（uint32 小端）+ 负载。

| type | 名称 | 负载 |
| --- | --- | --- |
| 1 | CONTROL | UTF-8 JSON |
| 2 | PCM | float32 LE 交错采样 |
| 3 | END | 空 |

控制命令：

```json
{"cmd":"configure","device":"default","sampleRate":48000,"channels":2,"bits":24,"sampleFormat":"s24le","exclusive":true,"bufferMs":10,"volume":1.0}
{"cmd":"start"}
{"cmd":"pause"}
{"cmd":"resume"}
{"cmd":"volume","value":0.6}
{"cmd":"flush"}
{"cmd":"stop"}
```

`sampleRate/channels/bits/sampleFormat` 描述**设备输出格式**；输入 PCM 永远是 float32。`auto` 由扩展在发送前解析成具体值。

### 事件

```json
{"event":"ready","version":"0.1.0","protocol":"1"}
{"event":"configured","device":{...},"format":{...},"bufferFrames":480,"exclusive":true}
{"event":"started"}
{"event":"progress","frames":48000,"playedFrames":47900}
{"event":"underrun","message":"..."}
{"event":"drained"}
{"event":"deviceLost","message":"..."}
{"event":"error","code":"FORMAT_UNSUPPORTED","message":"...","supported":[{...}]}
```

约束：

- `ready` 必须在 8 秒内出现，`configured` / `started` 各 10 秒。
- 错误必须带 `code` 与可读 `message`；格式不支持时带 `supported` 数组。
- 设备不支持时**不得静默降级**；宁可返回错误。
- `progress` 的 `playedFrames` 用于 UI 进度，缺失时客户端会退化到 `frames`。

## 编写一个原生后端

参考 `native/src/naoe.h` 的 `NaoeBackend`：

```c
typedef struct NaoeBackend {
  const char *name;
  int (*open)(const NaoeConfig *, NaoeFormat *, int *buffer_frames, void **handle,
              char *err, size_t err_len, char *supported, size_t supported_len);
  int (*write)(void *handle, const float *interleaved, int frames);
  int (*position)(void *handle, uint64_t *played_frames);
  void (*pause)(void *handle, int paused);
  void (*volume)(void *handle, double gain);
  void (*flush)(void *handle);
  int (*drain)(void *handle);
  void (*close)(void *handle);
  int (*probe)(const NaoeBackend *, char *json, size_t json_len);
} NaoeBackend;
```

`write` 可以阻塞；返回实际写入帧数，`-1` 表示可恢复错误（触发 underrun），`-2` 表示设备丢失。

## 构建原生组件

```bash
# 全部平台
node scripts/build-native.mjs

# 单个平台
node scripts/build-native.mjs linux-arm64
```

要求 zig 0.15.x；可以在 `tools/zig/zig`、`ZIG` 环境变量、`/tmp/toolchain/zig/zig` 或 PATH 中找到。ALSA 头文件已放在 `native/third_party/alsa`，不需要 root 安装 `libasound2-dev`。

产物写入 `components/<platform>-<arch>/`，脚本同时计算 SHA-256 并生成 `component.json`。

## 测试

无音频设备时：

```bash
NAOE_BACKEND=null ./components/linux-arm64/native-audio-output --probe
NAOE_BACKEND=null node test/native.test.mjs
```

`test/native.test.mjs` 会启动 `--serve`，走完 configure → start → PCM → END，并断言 `ready/configured/started/progress/drained` 事件顺序。

## 第三方 UI 组件

当前版本支持：

- 安装包含 `component.json` 的目录；
- 校验平台、入口与哈希；
- 在「组件」标签里启用 / 禁用 / 卸载。

`ui.entry` 指向组件自带的 Webview 资源，预留给后续版本动态挂载到「网易云音乐组件」视图容器。扩展不会执行第三方组件里的任意 Node 代码。

## 发布检查清单

- [ ] `component.json` 的 `id` / `version` 唯一且递增
- [ ] `platform` / `arch` 正确
- [ ] `sha256` 与实际入口一致（构建脚本会写入）
- [ ] `--probe` 在目标平台返回合法 JSON
- [ ] `--serve` 在无设备 / 错误格式下返回明确错误
- [ ] 不联网、不读用户文件、不修改系统设置
