## EAPI 传输

所有请求：

```
POST https://interface.music.163.com/eapi/<path minus /api>
Content-Type: application/x-www-form-urlencoded
params=<AES-128-ECB(key=e82ckenh8dichen8, PKCS#7) uppercase hex>
```

签名负载：

```
<path>-36cd479b6b5-<json>-36cd479b6b5-<md5("nobody"+path+"use"+json+"md5forencrypt")>
```

- `header` 对象包含 `os=pc`、`appver=3.1.17.204416`、`osver`、`deviceId`、`requestId`、`channel`、`versioncode`、`__csrf`、`MUSIC_U` / `MUSIC_A`。
- Cookie 同时带完整桌面指纹；只发 `os=pc` 会被风控（`-462`）。
- 响应若以 `#14` 开头，用同一 EAPI key AES-ECB 解密。
- 请求串行 + 最小间隔 180ms；风控 406 / -462 / -460 自动等待 8s 重试一次。
- 没有网页端 bootstrap、没有 Web 播放器接口。

## 页面与数据流

```
侧边栏点击
  → App.dispatch(nav/openPlaylist/...)
  → 拉取 EAPI 数据
  → MainPanelProvider.post({type:"page", page})
  → 主界面按 page.kind 渲染

歌单详情
  → /api/v6/playlist/detail (n=1000)
  → 若 tracks 不足：/api/v3/song/detail 按 500 分块补齐
  → /api/song/enhance/privilege 补 maxBrLevel（音质标签）
  → 评论 /api/v1/resource/comments/A_PL_0_<id>
  → 收藏者 /api/playlist/subscribers

播放
  → PlayerService.resolveUrl: /api/song/enhance/player/url/v1
  → 原生：下载到缓存 → sidebar webview fetch 本地 URI → OfflineAudioContext 源采样率解码
        → nativeBegin → 宿主启动引擎 → PCM 分块 → nativePcmAck → pcmDone → drained
  → WebAudio：remote URL → sidebar 隐藏 <audio>（不设 crossOrigin）
```

### 为什么 WebAudio 宿主在侧边栏

主界面面板关闭会销毁其 Webview。侧边栏使用 `retainContextWhenHidden: true`，把隐藏的 `<audio>` 和 PCM 解码桥放在侧边栏，关闭主界面不影响 WebAudio 播放；原生引擎由宿主进程直接输出，连侧边栏隐藏也不受影响。

## UI 状态

- `SidebarState`：账号、我喜欢、创建/收藏歌单、计数、当前导航。
- `PageView`：`recommend / featured / podcast / roam / following / playlist / album / artist / search / queue / downloads / recent / collections / local / cloud / now`。
- `SettingsState`：账号、`SettingsView`、音质选项、组件、原生引擎状态、当前标签。
- 所有设置写入 `settings.json`；折叠状态在 `neteaseMusic.ui.panels`。
- 播放队列 / 音量 / 模式 / 最近播放 / 喜欢集合写入 `globalState`。

## 音质与输出

- 7 档：`standard → exhigh → lossless → hires → jyeffect → sky → jymaster`。
- 音质只决定源文件；实际档位由 `/api/song/enhance/player/url/v1` 返回的 `level` 决定。
- `output.mode=auto` 优先原生；`native` 失败不回退；`webaudio` 仅 WebAudio。
- 原生引擎不做重采样；手动采样率必须等于音源。WASAPI Shared 由系统转换，不是 bit-perfect。

## 原生引擎握手

1. 宿主 `spawn(binary, ["--serve"])`。
2. stdout `{"event":"ready","version":"0.1.0","protocol":"1"}`。
3. `configure`：`device,sampleRate,channels,bits,sampleFormat,exclusive,bufferMs,volume`。
4. 引擎打开设备，输出 `configured`（实际格式、bufferFrames、exclusive），失败输出 `error` + `supported`。
5. `start` → 播放线程 → `started`。
6. PCM 帧（5 字节头 + f32le）→ `progress`。
7. END → drain → `drained`。

## 安全与边界

- Cookie 存 SecretStorage，日志不打印 Cookie / 密码。
- 原生引擎不联网、不解码、不读用户文件，只接收 stdin PCM。
- 所有 Webview 使用 CSP + nonce；远程图片只允许 https/data。
- 第三方 UI 组件只支持清单、安装、启停、卸载，不执行未签名代码。
